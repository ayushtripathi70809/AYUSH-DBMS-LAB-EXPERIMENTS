# Experiment 9: Railway Booking and Index Optimization

## Aim

To create a Railway Booking table containing at least 5,000 records and benchmark query performance before and after creating single and composite indexes. To compare query execution plans using the EXPLAIN command.

## Requirements

* MySQL 8.0 or above
* MySQL Workbench or MySQL Command Line Client

## Description

This experiment demonstrates the use of indexing to improve query performance in a Railway Booking database. A table containing at least 5,000 records is created. Queries are executed before and after creating single-column and composite indexes, and their execution plans are compared using EXPLAIN.

## Procedure

1. Create the Railway Booking table.
2. Insert at least 5,000 records into the table.
3. Execute sample queries before creating indexes.
4. Analyze query execution plans using EXPLAIN.
5. Create a single-column index.
6. Create a composite index on multiple columns.
7. Execute the queries again after indexing.
8. Compare the execution plans and query performance.

## Concepts Used

* Database Indexing
* Single-Column Index
* Composite Index
* Query Performance Benchmarking
* EXPLAIN Command
* Query Optimization

## Expected Output

* A Railway Booking table containing at least 5,000 records.
* Execution plans before indexing.
* Execution plans after creating single and composite indexes.
* Comparison of query performance before and after optimization.

## Result

The Railway Booking table is created with at least 5,000 records. Single-column and composite indexes are implemented, and query execution plans are compared using EXPLAIN to evaluate their effect on query performance.
